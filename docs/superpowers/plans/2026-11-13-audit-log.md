# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record every read and write of a secret on this device, and show it with `kerstel audit` and an Audit screen in `kerstel ui`, reveals first.

**Architecture:** The vault store writes the rows for writes itself (`setSecret`, `removeSecret`, `applyRemote`, `keepLocal`), stamped with the actor the vault was opened with, so no write path can forget one. Reveals, runs, and device events are recorded by their commands through `vault.record()`. The daemon stamps `resolve` rows with the requesting process's parent chain and working directory. One report module (`src/audit/report.ts`) feeds both the CLI command and the UI screen.

**Tech Stack:** TypeScript on Bun 1.4.2, `bun:sqlite`, `bun test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-13-access-gating-design.md`, Part A (§4). Background: `docs/superpowers/specs/2026-09-19-terminal-ui-design.md` §4 (UI model).

## Global Constraints

- A row never holds a value, a hash, a length, or any part of one. No test prints a value; assertions check for absence.
- Tests use `test/helpers/isolate-env.ts` and clean up their temp homes and vaults.
- Status lines on stderr use `process.stderr.write`, never `console.error` (Bun paints it red on a TTY). Command names in copy use `cliName()`.
- Exit codes: `0` success whatever the log holds, `2` for bad usage (unknown flag, unknown `--action`, bad `--since` or `--limit`).
- Retention: 90 days (`AUDIT_RETENTION_MS = 90 * 24 * 60 * 60 * 1000`). Summary period default: 7 days. Default `--limit`: 50 per section. UI page: 200 rows.
- Parent chain: names only, never arguments; at most 6 names; joined for display with ` ← `.
- Audit rows stay on this device; nothing here touches the sync record format.
- `CHANGELOG.md` and `ROADMAP.md` links are absolute (`https://kerstel.dev/...`). `docs/` is rebuilt with `bun run --cwd apps/website build` and committed.
- Branch `feat/audit-log`, Conventional Commits, PR says `Closes #11`.

## Review Focus

1. **`ps` missing or failing** (minimal containers, sandboxed shells): the chain is `[]`, the write still succeeds, and the audit shows `unknown`. Pinned in Task 2 and Task 3.
2. **Working directory matching**: a monorepo member inside a registered root matches the deepest registered root; `/code/web2` does not match a root of `/code/web`; a directory outside every root gives no project. Pinned in Task 1.
3. **A log written before this version** (no `chain`, no project): rows render with `unknown` in the CLI and the UI, without crashing. Pinned in Task 6 and Task 7.
4. **A reveal of a secret that has since changed or been removed**: no rotation hint, and nothing is decrypted for a removed secret. Pinned in Task 6.
5. **The value of a revealed credential appears nowhere** in `kerstel audit` output or the UI rows. Pinned in Task 6 and Task 7.

- Rules for `processChain`: start with `pid`'s own name; follow `ppid`; a name is the basename of the command with one leading `-` removed (login shells); stop before `launchd`, `systemd`, `init`, `kernel_task`, or pid ≤ 1; include a terminal name and stop after it (`Terminal`, `iTerm2`, `ghostty`, `kitty`, `alacritty`, `wezterm-gui`, `gnome-terminal-server`, `konsole`, `xterm`, `tmux`, `sshd`); at most 6 names; stop on a pid already seen; a lookup that returns `null` ends the chain.
- `systemProcessLookup`: on macOS, one `ps -axo pid=,ppid=,comm=` snapshot taken on first call (via `Bun.spawnSync`), parsed into a map; on Linux, read `/proc/<pid>/stat` per call (the name is between the first `(` and the last `)`, `ppid` is the second field after it). Any failure (no `ps`, non-zero exit, unreadable `/proc`) yields a lookup that returns `null`. It never throws.
